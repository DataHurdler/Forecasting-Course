\section{From Trees to Neural Networks}
% =============================================================================

\sectionslide{From Trees to Neural Networks}{%
  Trees predict in steps. Networks predict in curves --- and that difference
  buys less than you would expect on tabular data, and everything on sequences.}

% --- Slide: Motivation -------------------------------------------------------
\begin{frame}{Why Go Beyond Trees?}
  A tree-based model treats every row as independent. Order is not part of the model ---
  everything it knows about time, you put there by hand, as lag columns and rolling means.
  And its prediction is \textbf{piecewise constant}, which is why in Lab 4 the tree could not
  predict above the largest value it had seen.

  \vspace{0.15cm}
  A neural network learns a \textbf{smooth, continuous} function instead. Its architecture is
  not fixed: the same machinery adapts to sequences, images and text, and it can learn its own
  intermediate representations rather than being handed engineered ones.

  \begin{warningbox}
    \textbf{This is not an upgrade.} On the tabular problems of Homework 3 and 4, gradient
    boosting and a tuned LASSO were hard to beat, and a network will often lose to both. Reach
    for one when the data is a \emph{sequence}, when the raw input is an image or audio, or when
    $n$ is very large. Otherwise you are paying in tuning time for accuracy you will not get.
  \end{warningbox}

  \vspace{0.1cm}
  So today is about the machinery. Lectures 8 and 9 are where it earns its place.
\end{frame}

% --- Slide: From regression to a neuron ---------------------------------------
\begin{frame}{From Linear Regression to a Single Neuron}
  Start from something you already know. Linear regression predicts
  $\hat{y} = \mathbf{w}^\top \mathbf{x} + b$.

  \vspace{0.15cm}
  A \textbf{neuron} is that same expression with one addition --- a nonlinear
  \textbf{activation} $\sigma(\cdot)$ wrapped around it:
  \[
    a = \sigma(\mathbf{w}^\top \mathbf{x} + b)
  \]
  \vspace{-0.35cm}
  \begin{center}
    {\footnotesize
    \begin{tabular}{lll}
      \toprule
      \textbf{Activation} & \textbf{Formula} & \textbf{Where it is used} \\
      \midrule
      ReLU    & $\max(0,z)$       & Hidden layers --- the default \\
      Sigmoid & $1/(1+e^{-z})$    & Binary outputs, and LSTM gates (Lecture 9) \\
      Tanh    & $\tanh(z)$        & Sequence states \\
      Linear  & $z$               & The output layer, for regression \\
      \bottomrule
    \end{tabular}
    }
  \end{center}

  \vspace{0.1cm}
  ReLU makes the intuition literal: the neuron asks \emph{``is this pattern present?''} If the
  evidence is positive it passes a signal through; if not it outputs exactly zero and stays
  silent.
\end{frame}

% --- Slide: why nonlinearity ---------------------------------------------------
\begin{frame}{Why the Nonlinearity Is the Whole Trick}
  It is worth being precise about what $\sigma(\cdot)$ buys, because it is easy to assume that
  depth alone is what makes a network powerful. It is not.

  \begin{definitionbox}{Stacking linear layers gains you nothing}
    A linear function of a linear function is linear. Compose two layers with no activation
    between them and you get $\mathbf{W}_2(\mathbf{W}_1\mathbf{x}) = (\mathbf{W}_2\mathbf{W}_1)\mathbf{x}$
    --- a single matrix, and therefore a single linear model with extra steps.
  \end{definitionbox}

  \vspace{0.1cm}
  Insert a nonlinearity between the layers and the picture changes completely. The
  \textbf{universal approximation theorem} says a network with one hidden layer can approximate
  \emph{any} continuous function to arbitrary accuracy, given enough neurons.

  \vspace{0.1cm}
  \textbf{Read that claim carefully.} It says a network \emph{can} represent the function --- not
  that your optimizer will find it, that you have the data to identify it, or that it will
  generalize. Existence is not estimation, the same gap as between the optimal tree and the
  greedy one CART builds.
\end{frame}

\section{Feedforward Networks}
% =============================================================================

\sectionslide{Feedforward Networks}{%
  Stack layers of neurons, and each layer learns a higher-level
  representation of the one below it.}

% --- Slide: Layers and forward pass ------------------------------------------
\begin{frame}{Feedforward Network: Layers and Forward Pass}
  A \textbf{feedforward network} --- an FFN, or multilayer perceptron --- is three things
  in sequence. An \textbf{input layer} of raw features $\mathbf{x} \in \mathbb{R}^p$; some number
  of \textbf{hidden layers}, each applying
  $\mathbf{a}^{(\ell)} = \sigma\!\left(\mathbf{W}^{(\ell)}\mathbf{a}^{(\ell-1)} + \mathbf{b}^{(\ell)}\right)$;
  and an \textbf{output layer} that is linear for regression.

  \vspace{0.15cm}
  Two words you need: \textbf{width} is the number of neurons in a layer, \textbf{depth} is the
  number of hidden layers. Together they set the model's capacity.

  \begin{keybox}
    \textbf{Sensible starting sizes for forecasting:} 2--3 hidden layers, 64--256 neurons each,
    ReLU activations, dropout between 0.2 and 0.5. Start at the small end of every range.
  \end{keybox}

  \vspace{0.1cm}
  Bigger is not better on its own. A wider or deeper network needs more data and more
  regularization to reach the same generalization, so add capacity only when validation error
  says the current model is genuinely too simple --- not because it is available.
\end{frame}

% --- Slide: counting parameters ------------------------------------------------
\begin{frame}{How Big Is This Model, Actually?}
  Capacity is easy to add by accident, so it is worth counting once. A layer mapping $m$ inputs
  to $n$ outputs holds $m \times n$ weights plus $n$ biases.

  \vspace{0.1cm}
  Take a network for our weekly panel: 46 engineered features in, two hidden layers of 128, one
  output.
  \begin{center}
    {\small
    \begin{tabular}{lrr}
      \toprule
      \textbf{Layer} & \textbf{Shape} & \textbf{Parameters} \\
      \midrule
      Input $\rightarrow$ hidden 1 & $46 \times 128$ & 6{,}016 \\
      Hidden 1 $\rightarrow$ hidden 2 & $128 \times 128$ & 16{,}512 \\
      Hidden 2 $\rightarrow$ output & $128 \times 1$ & 129 \\
      \midrule
      \textbf{Total} & & \textbf{22{,}657} \\
      \bottomrule
    \end{tabular}
    }
  \end{center}

  \textbf{Twenty-two thousand parameters on five thousand rows} --- four per observation.

  \vspace{0.1cm}
  Lecture 6 called sixty predictors on a hundred and fifty observations a crisis. This is far
  past that ratio, and networks train here routinely. What makes it survivable is not the
  architecture but the regularization, next.
\end{frame}

\section{Training: Loss and Backpropagation}
% =============================================================================

\sectionslide{Training: Loss and Backpropagation}{%
  Compute the error, propagate it backward, adjust every weight
  by its share of the blame. Repeat.}

% --- Slide: Loss and SGD -----------------------------------------------------
\begin{frame}{Training: Loss, Gradients, and the Update Step}
  Training is one loop, repeated. \textbf{First}, compute the loss --- for regression, mean
  squared error, $\mathcal{L} = \frac{1}{n}\sum_i (y_i - \hat{y}_i)^2$.

  \vspace{0.1cm}
  \textbf{Second, backpropagation:} work backward through the network, using the chain rule to
  assign each weight its share of the error. \textbf{Third}, nudge every weight against its
  gradient:
  \[
    \mathbf{W} \leftarrow \mathbf{W} - \eta \, \frac{\partial \mathcal{L}}{\partial \mathbf{W}},
    \qquad \eta = \text{learning rate}
  \]
  \vspace{-0.3cm}
  \begin{definitionbox}{Stochastic gradient descent}
    Rather than using the whole dataset for each update, use a random \textbf{mini-batch} of
    32--256 rows. Noisier steps, far more of them, and much faster. One pass through every batch
    is an \textbf{epoch}.
  \end{definitionbox}

  \textbf{You never differentiate by hand.} \texttt{loss.backward()} does the backward pass, and
  \texttt{torch.optim.Adam(lr=1e-3)} beats plain SGD --- it adapts the step size per parameter.
\end{frame}

% --- Slide: Overfitting and regularization ------------------------------------
\begin{frame}{Preventing Overfitting --- Where Lecture 6 Returns}
  Twenty-two thousand parameters on five thousand rows will memorize the training set unless
  something stops it. Three things do, and \textbf{you have met two of them already}.

  \vspace{0.1cm}
  \begin{center}
    {\small
    \begin{tabular}{p{3.0cm}p{9.4cm}}
      \toprule
      \texttt{weight\_decay} & \textbf{This is Ridge.} An $\ell_2$ penalty on the weights, under
      a different name. \texttt{Adam(..., weight\_decay=1e-4)} \\[3pt]
      \texttt{nn.Dropout(p)} & Randomly zero a fraction $p$ of neuron outputs on each forward
      pass, so no neuron can depend on a specific other one being present. All neurons are
      active at test time. \\[3pt]
      Early stopping & Watch validation loss each epoch; stop when it has not improved for
      $k$ epochs, and keep the weights from the \emph{best} epoch, not the last. \\
      \bottomrule
    \end{tabular}
    }
  \end{center}

  \vspace{0.1cm}
  \textbf{That is the fifth appearance of one idea.} The GAM smoothing penalty in Lecture 3,
  cost-complexity pruning in Lecture 4, \texttt{reg\_lambda} on leaf weights in Lecture 5,
  Ridge and LASSO in Lecture 6 --- and now weight decay. Fit against complexity, one parameter
  setting the exchange rate, chosen by validation.
\end{frame}

\section{PyTorch Implementation}
% =============================================================================

\sectionslide{PyTorch Implementation}{%
  Four pieces: a Dataset, a DataLoader, a model, and a training loop.}

% --- Slide: PyTorch Dataset and DataLoader -----------------------------------
\begin{frame}{PyTorch: Dataset and DataLoader}
  \begin{examplebox}{Wrapping your arrays}
    {\tiny\linespread{1.2}\selectfont
    \texttt{from torch.utils.data import Dataset, DataLoader}\\[2pt]
    \texttt{class ForecastDataset(Dataset):}\\
    \texttt{\ \ def \_\_init\_\_(self, X, y):}\\
    \texttt{\ \ \ \ self.X = torch.tensor(X, dtype=torch.float32)}\\
    \texttt{\ \ \ \ self.y = torch.tensor(y, dtype=torch.float32)}\\
    \texttt{\ \ def \_\_len\_\_(self): return len(self.X)}\\
    \texttt{\ \ def \_\_getitem\_\_(self, i): return self.X[i], self.y[i]}\\[3pt]
    \texttt{loader = DataLoader(ForecastDataset(X\_tr, y\_tr),}\\
    \texttt{\ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ batch\_size=64, shuffle=False)}
    }
  \end{examplebox}
  \texttt{Dataset} fetches \emph{one} example; \texttt{DataLoader} handles batching.

  \vspace{0.1cm}
  \textbf{Note \texttt{shuffle=False}.} Nearly every tutorial sets it \texttt{True} --- right for
  images, wrong here. It destroys the ordering your lag features depend on.
\end{frame}

% --- Slide: model definition -------------------------------------------------
\begin{frame}{PyTorch: Defining the Model}
  \begin{examplebox}{A two-layer network with dropout}
    {\scriptsize\linespread{1.15}\selectfont
    \texttt{import torch.nn as nn}\\[2pt]
    \texttt{model = nn.Sequential(}\\
    \texttt{\ \ \ \ nn.Linear(n\_features, 128), nn.ReLU(), nn.Dropout(0.3),}\\
    \texttt{\ \ \ \ nn.Linear(128, 128),\ \ \ \ \ \ nn.ReLU(), nn.Dropout(0.3),}\\
    \texttt{\ \ \ \ nn.Linear(128, 1))}
    }
  \end{examplebox}
  Read it top to bottom and it is the diagram: a linear map, a nonlinearity, some dropout,
  again, then a linear output with no activation because this is regression.

  \vspace{0.15cm}
  \texttt{nn.Sequential} chains layers in order and is enough for anything in this lecture. When
  an architecture needs branching or a skip connection --- Lecture 8 --- you subclass
  \texttt{nn.Module} and write \texttt{forward()} yourself.

  \vspace{0.15cm}
  \muted{\footnotesize\itshape \texttt{nn.Linear(in, out)} holds the weight matrix and bias for
  one layer. That is where the 22{,}657 parameters live.}
\end{frame}

% --- Slide: training loop ----------------------------------------------------
\begin{frame}{PyTorch: The Training Loop}
  \begin{examplebox}{The four steps, per mini-batch}
    {\tiny\linespread{1.2}\selectfont
    \texttt{opt = torch.optim.Adam(model.parameters(), lr=1e-3, weight\_decay=1e-4)}\\
    \texttt{lossfn = nn.MSELoss()}\\[3pt]
    \texttt{for epoch in range(n\_epochs):}\\
    \texttt{\ \ model.train()}\\
    \texttt{\ \ for xb, yb in loader:}\\
    \texttt{\ \ \ \ opt.zero\_grad()\ \ \ \ \ \ \ \ \ \ \ \ \ \ \# 1 clear old gradients}\\
    \texttt{\ \ \ \ loss = lossfn(model(xb).squeeze(), yb)\ \# 2 forward}\\
    \texttt{\ \ \ \ loss.backward()\ \ \ \ \ \ \ \ \ \ \ \ \ \ \# 3 backward}\\
    \texttt{\ \ \ \ opt.step()\ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \# 4 update weights}
    }
  \end{examplebox}
  Every PyTorch training loop is those four lines with more around them.

  \vspace{0.1cm}
  \textbf{The one that bites:} forget \texttt{zero\_grad()} and PyTorch \emph{accumulates} gradients
  rather than replacing them. No error, no warning --- just a model that trains badly.
\end{frame}

\section{Key Takeaways}
% =============================================================================

\sectionslide{Key Takeaways}{%
  Where a network belongs in the toolkit you now have.}

% --- Slide: comparison -------------------------------------------------------
\begin{frame}{Neural Networks vs.\ Tree Methods \parencite{James2021}}
  \begin{center}
    {\small
    \begin{tabular}{lllll}
      \toprule
      \textbf{Method} & \textbf{Sequences} & \textbf{Extrapolates} & \textbf{Tuning} & \textbf{Best for} \\
      \midrule
      LASSO / Ridge & no & yes & light & Many correlated predictors \\
      Random forest & no & no & light & Tabular, robust default \\
      XGBoost & no & no & moderate & Tabular, best-in-class \\
      FFN & no & yes & heavy & Smooth functions, large $n$ \\
      RNN / LSTM & \textbf{yes} & yes & heavy & Sequences (Lecture 9) \\
      \bottomrule
    \end{tabular}
    }
  \end{center}

  \vspace{0.15cm}
  \textbf{An FFN on lag features is doing the same job as XGBoost on lag features} --- same
  inputs, same flat table, no notion of order. It is not obviously the better tool, and on the
  evidence of Homework 4 it usually is not.

  \vspace{0.15cm}
  What changes in the next two lectures is the \emph{architecture}: convolutions that see local
  structure, and recurrence that carries state through time. That is when the sequence column
  above starts saying yes, and it is the reason to learn this machinery now.
\end{frame}

% --- Slide: Key takeaways ---------------------------------------------------
\begin{frame}{Lecture 7: Key Takeaways}
  \begin{keybox}
    {\footnotesize
    \begin{enumerate}\itemsep2pt
      \item A \textbf{neuron} is linear regression wrapped in a nonlinear activation. Without
            the nonlinearity, stacking layers collapses back to one linear model.

      \item An \textbf{FFN} stacks those layers. Width and depth set capacity, and capacity
            accumulates faster than you expect --- 22{,}657 parameters on 5{,}000 rows.

      \item \textbf{Training} is one loop: loss $\to$ \texttt{backward()} $\to$
            \texttt{step()}, on mini-batches, using Adam. You never differentiate by hand.

      \item \textbf{Regularization is not new.} Weight decay is Ridge; dropout and early
            stopping do the same job by other means. Fifth appearance of one idea.

      \item For time series: \textbf{do not shuffle} the DataLoader, split by time, and call
            \texttt{zero\_grad()} every batch.

      \item An FFN on engineered features is a competitor to XGBoost, \textbf{not an upgrade}.
            Architecture is what earns its keep --- next two lectures.
    \end{enumerate}
    }
  \end{keybox}
  \muted{\itshape Next: CNN architectures --- convolution, pooling, and 1D convolutions
  for time series.}
\end{frame}
