10  Lab 9 Part 2: Attention — and the Line You Cannot Forget

Run this one live: the executable lab.

10.1 What we are doing

Last week’s recurrent models read the window one step at a time. Attention does not: every position looks at every other position at once, so week 3 reaches week 50 in a single operation rather than through forty-seven state updates.

Today you build a Transformer encoder, then delete one line from it and watch it fall apart. That line is the one PyTorch does not add for you, and forgetting it is the most common way this architecture fails silently.

Suggested time: ~40 minutes · You will need: pandas, numpy, matplotlib, torch, and data/processed/m5_weekly.csv.

This lab is slow

Attention is \(O(T^2)\) in sequence length, and we use a 52-week window. A single fit takes about 70 seconds and Step 3 trains four of them. Start the cell, read while it runs.

10.2 Setup

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import math
import torch
import torch.nn as nn
import warnings
warnings.filterwarnings('ignore')

from pathlib import Path

def data_path(name):
    for base in (Path.cwd(), *Path.cwd().parents):
        p = base / "data" / "processed" / name
        if p.exists():
            return p
    raise FileNotFoundError(
        f"Could not find data/processed/{name}. "
        "Run `python scripts/prep_m5.py` from the repository root first.")

weekly = (pd.read_csv(data_path("m5_weekly.csv"), parse_dates=["week_start"])
            .sort_values(["store_id", "cat_id", "week_start"]))
CHANNELS, WINDOW = ["units", "snap_days", "event_days", "avg_price"], 52
CUTOFF = np.datetime64("2015-05-17")
rmse = lambda a, b: float(np.sqrt(np.mean((np.asarray(a) - np.asarray(b)) ** 2)))

X, Y, D = [], [], []
for _, g in weekly.groupby(["store_id", "cat_id"]):
    arr, dates = g[CHANNELS].values.astype("float32"), g.week_start.values
    for i in range(len(g) - WINDOW):
        X.append(arr[i:i+WINDOW]); Y.append(arr[i+WINDOW, 0]); D.append(dates[i+WINDOW])
X = np.stack(X); Y = np.array(Y, dtype="float32"); D = np.array(D)
tr, te = D < CUTOFF, D >= CUTOFF
mu, sd = X[tr].mean((0,1), keepdims=True), X[tr].std((0,1), keepdims=True) + 1e-8
ym, ys = Y[tr].mean(), Y[tr].std()
Xn, Yn = (X - mu)/sd, (Y - ym)/ys
X_tr, y_tr, X_te = torch.tensor(Xn[tr]), torch.tensor(Yn[tr]), torch.tensor(Xn[te])
print(f"{X.shape[0]:,} windows of {WINDOW} weeks — train {tr.sum():,}, test {te.sum():,}")
Walkthrough

Same panel, same cutoff, same standardization. One difference from the recurrent lab: the window is fixed at 52 weeks throughout, because a long window is where attention is supposed to earn its keep. If direct long-range paths are worth anything, a full year of history is where we should see it.

That choice is also why this lab is slow. Attention compares every position with every other position, so the cost grows with the square of the window. Fifty-two weeks means 2,704 pairwise comparisons per example per head per layer.

10.3 Step 1 — Positional encoding, before the model

Attention computes a weighted average over positions. Averaging does not care about order: shuffle the input and every attention output is unchanged.

So position has to be added to the input itself. The standard device is a set of sinusoids of different frequencies.

def sinusoidal(seq_len, d_model):
    pe = torch.zeros(seq_len, d_model)
    pos = torch.arange(seq_len).unsqueeze(1).float()
    div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
    pe[:, 0::2] = torch.sin(pos * div)
    pe[:, 1::2] = torch.cos(pos * div)
    return pe.unsqueeze(0)

pe = sinusoidal(WINDOW, 64)
fig, ax = plt.subplots(figsize=(9, 3))
im = ax.imshow(pe[0].T, aspect="auto", cmap="RdBu")
ax.set_xlabel("week in window"); ax.set_ylabel("encoding dimension")
plt.colorbar(im); plt.tight_layout()

Read the picture. Every column — every week — has a distinct pattern down the dimensions, so the model can tell positions apart. Nearby columns look similar, so it can also learn relative distance rather than only absolute index.

Walkthrough

Start with the problem, because the solution makes no sense without it.

Attention computes a weighted average over positions. And an average does not care about order — reverse the sequence, shuffle it, deal it like a deck of cards, and every attention output is identical. The mechanism is permutation-invariant by construction.

That is a catastrophe for forecasting. “Sales were 3,000 last week and 9,000 a year ago” and “sales were 9,000 last week and 3,000 a year ago” are the same bag of numbers and completely different futures.

So position has to be put into the input itself, before attention ever sees it. The standard device is a set of sinusoids at different frequencies.

Try it

Pause on the heat map and check two properties before I name them.

One: every column is distinct. Each week has its own signature down the 64 dimensions, so the model can tell position 3 from position 47.

Two, and this is the part people miss: nearby columns look similar. Week 20 and week 21 have almost the same pattern; week 20 and week 50 do not. That means the encoding carries relative distance, not just an arbitrary label per slot. A model can learn “about four weeks apart” as a concept rather than memorizing every pair of indices — which is what makes the scheme work at positions it never saw in training.

That is why sinusoids rather than, say, just numbering the weeks 1 to 52.

10.4 Step 2 — Build the encoder

class TransformerForecaster(nn.Module):
    def __init__(self, n_channels=4, d_model=64, nhead=4, layers=2, use_pe=True):
        super().__init__()
        self.use_pe = use_pe
        self.inp = nn.Linear(n_channels, d_model)
        self.register_buffer("pe", sinusoidal(WINDOW, d_model))
        enc_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead, dim_feedforward=128,
            dropout=0.1, batch_first=True)
        self.enc = nn.TransformerEncoder(enc_layer, num_layers=layers)
        self.fc = nn.Linear(d_model, 1)

    def forward(self, x):
        h = self.inp(x)
        if self.use_pe:
            h = h + self.pe                 # <- the line in question
        return self.fc(self.enc(h)[:, -1, :]).squeeze(-1)

def train(use_pe, seed, epochs=30):
    torch.manual_seed(seed)
    model = TransformerForecaster(use_pe=use_pe)
    opt = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-4)
    lossfn = nn.MSELoss()
    loader = torch.utils.data.DataLoader(
        torch.utils.data.TensorDataset(X_tr, y_tr), batch_size=128, shuffle=False)
    for _ in range(epochs):
        model.train()
        for xb, yb in loader:
            opt.zero_grad()
            lossfn(model(xb), yb).backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt.step()
    model.eval()
    with torch.no_grad():
        return rmse(Y[te], model(X_te).numpy() * ys + ym), sum(p.numel() for p in model.parameters())

score, n_par = train(use_pe=True, seed=1)
print(f"Transformer — {n_par:,} parameters, test RMSE {score:,.0f}")

Note the parameter count against last week’s models: the RNN had 4,545 and won.

Walkthrough

The whole architecture is four objects: a linear layer lifting 4 channels to 64 dimensions, the positional encoding, two TransformerEncoderLayers, and a linear head reading the final position.

That line is the subject of the lab. One addition. Everything else in this class is supplied by PyTorch.

Transformer — 67,329 parameters, test RMSE 1,013

Sixty-seven thousand parameters. Hold that against last week: the vanilla RNN had 4,545 and scored 805. So attention arrives with fifteen times the parameters of the model it needs to beat.

10.5 Step 3 — Delete the line

Same model, same data, same seeds — use_pe=False removes the single addition in forward.

rows = []
for use_pe in (True, False):
    runs = [train(use_pe, s)[0] for s in (1, 2)]
    rows.append({"positional encoding": "yes" if use_pe else "no",
                 "mean": round(np.mean(runs)), "sd": round(np.std(runs)),
                 "runs": [round(r) for r in runs]})
print(pd.DataFrame(rows).to_string(index=False))
Nothing raised an exception

The model without positional encoding trained happily, converged, and returned forecasts. It was simply working from an unordered bag of 52 weeks — it could not tell last week from a year ago.

Compare the gap against the run-to-run spread in the sd column. This is not noise.

nn.TransformerEncoderLayer gives you attention, residuals, layer norm and the feed-forward sublayer. It does not give you position. That is yours to add, and nothing checks that you did.

The model without positional encoding trained for thirty epochs. The loss went down. It converged. It returned forecasts in the right units, in the right shape, with a plausible RMSE that is better than the seasonal-naive benchmark of 2,152. If you had no comparison to make, you would ship it.

What it was actually doing is working from an unordered bag of 52 weeks. It could not distinguish last week from a year ago. It knew what the year contained and nothing about when.

Look at the sd column before anyone asks. The two conditions have spreads of 23 and 8 against a gap of 292 — twelve to thirty-six times the noise. By the standard Lab 7 set, this is about as unambiguous as a result gets.

The practical warning: nn.TransformerEncoderLayer hands you attention, residual connections, layer normalization and the feed-forward sublayer. It does not hand you position, there is no default, and nothing checks that you added it. In a language model you would notice, because the output would be word salad. In a forecaster the output is a number, and numbers always look fine.

Every advantage attention has is an advantage at scale. Parallel computation across positions matters when a sequence is thousands of steps and a corpus is billions of tokens. Direct long-range paths matter when the signal genuinely sits far back. Neither describes 5,900 windows of weekly retail demand.

Read it honestly. The Transformer beats the CNN. It ties the LSTM — 990 against 998, a gap of 8 when the run-to-run spread is 23, so those two are indistinguishable. And it loses to the vanilla RNN by 185, on fifteen times the parameters.

Nothing here is a failed implementation. This is the architecture working correctly on a problem it was not designed for. And that is the point worth carrying. Every advantage attention has is an advantage at scale.

Parallel computation across positions is transformative when your sequence is thousands of steps and your corpus is billions of tokens — an RNN has to walk the sequence one step at a time, and a Transformer does not. Direct paths between distant positions matter when the signal genuinely sits far back and must survive the journey.

Neither describes 5,160 training windows of weekly retail demand, where the answer is mostly in the last few weeks. You are paying for a mechanism whose benefits do not exist at this size, with parameters that have to be estimated from data you do not have.
