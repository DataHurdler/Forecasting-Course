18  Homework 3: Decision Trees and Random Forests

19 Overview

This homework shifts from time series methods to machine learning approaches for forecasting. Decision trees and random forests reframe the problem as supervised learning: rather than modeling a single series through time, each store-category-week row becomes an independent training example, and lagged unit sales carry the temporal information that would otherwise live inside a model like ARIMA or ETS. These methods require no stationarity assumptions and discover nonlinear interactions automatically — for example, the effect of a SNAP benefit week may differ sharply between food and hobby categories, and a tree will split on both features without any manual interaction term.

Learning objectives. By the end of this assignment you will be able to:

  • Engineer lag and calendar features to turn a time series problem into a supervised learning problem
  • Fit and visualize a decision tree, and connect the splitting structure to business intuition
  • Fit a Random Forest and interpret its out-of-bag (OOB) error estimate
  • Compare mean decrease in impurity (MDI) vs permutation feature importance and articulate when each is trustworthy
  • Implement a walk-forward cross-validation loop for tree-based models

20 Dataset and Feature Engineering

Unlike ETS and ARIMA, which model one series at a time and require careful handling of seasonality and trend, tree-based models can use all 30 series simultaneously. The M5 extract holds 10 Walmart stores across 3 states, each with 3 product categories — 30 store-category series in all. Each store-category-week is a row in a flat table; the lag features encode how that particular series was performing recently. The model learns general rules that hold across series rather than fitting a separate process to each.

The preprocessed file is data/processed/m5_weekly.csv. If it does not exist, run python scripts/prep_m5.py once from the repository root.

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from sklearn.tree import DecisionTreeRegressor, export_text, plot_tree
from sklearn.ensemble import RandomForestRegressor

from pathlib import Path

def data_path(name):
    """Find the processed data file whether you render from the repo root or from
    this file's own folder."""
    for base in (Path.cwd(), *Path.cwd().parents):
        p = base / "data" / "processed" / name
        if p.exists():
            return p
    raise FileNotFoundError(
        f"Could not find data/processed/{name}. "
        "Run `python scripts/prep_m5.py` from the repository root first."
    )

RANDOM_STATE = 42

weekly = pd.read_csv(data_path("m5_weekly.csv"), parse_dates=["week_start"])
weekly["month"] = weekly["week_start"].dt.month
weekly["week_of_year"] = weekly["week_start"].dt.isocalendar().week.astype(int)
weekly["year"] = weekly["week_start"].dt.year

# store_id, cat_id and state_id are categorical. Trees in scikit-learn need numbers,
# so one-hot encode them. This is why the feature count is larger than it first looks.
df_enc = pd.get_dummies(weekly, columns=["store_id", "cat_id", "state_id"],
                        prefix=["store", "cat", "state"])

LAG_FEATURES = ["units_lag1", "units_lag2", "units_lag3", "units_lag4", "units_lag52"]
FEATURES = (LAG_FEATURES
            + ["avg_price", "snap_days", "event_days", "month", "week_of_year", "year"]
            + [c for c in df_enc.columns if c.startswith(("store_", "cat_", "state_"))])
TARGET = "units"

# Drop rows with missing lag features (the first 52 weeks of each series)
df = df_enc.dropna(subset=LAG_FEATURES).copy()
print(f"Modeling dataset: {len(df):,} store-category-week rows, "
      f"{weekly.groupby(['store_id','cat_id']).ngroups} series, {len(FEATURES)} features")

22.3 Q3 — Random Forest

(Suggested prompts: 2)

A Random Forest grows many decision trees on bootstrap samples of the data and averages their predictions. By training each tree on a different random subset of rows — and considering only a random subset of features at each split — the ensemble reduces the variance that makes individual deep trees unreliable. One by-product of bootstrap sampling is that roughly one-third of the training rows are left out of each tree: these out-of-bag (OOB) samples can be used to produce an internal validation score without touching the held-out test set.

22.4 Q4 — MDI vs Permutation Importance

(Suggested prompts: 2)

MDI importance measures how much each feature reduces impurity across all trees in the forest. It is fast to compute because it is a by-product of training, but it has a known bias: features with many distinct numeric values tend to receive inflated importance scores simply because they offer the splitter more places to cut, not because they carry more information.

Permutation importance avoids this bias by directly measuring how much accuracy degrades when a single feature’s values are randomly shuffled on the test set. A feature that matters will cause a large increase in RMSE when shuffled; a redundant or spurious one will cause almost none.

(a) Plant two controls. Add two columns of pure noise to the modeling table — one continuous, one binary — and refit the forest with them included:

df["noise_continuous"] = rng.rand(len(df))          # uniform on [0, 1)
df["noise_binary"] = rng.randint(0, 2, len(df))     # 0 or 1

FEATURES_WITH_NOISE = FEATURES + ["noise_continuous", "noise_binary"]

# Refit the Random Forest (same settings as Q3) using FEATURES_WITH_NOISE
