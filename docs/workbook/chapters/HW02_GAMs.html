17  Homework 2: Generalized Additive Models

18 Overview

Generalized Additive Models (GAMs) extend linear regression by replacing straight-line effects with flexible smooth functions — one per predictor — that are then added together to produce a forecast. This structure preserves interpretability (you can inspect each component individually) while capturing nonlinear patterns that fixed-slope models miss. Prophet, developed at Meta, applies exactly this idea to time series by decomposing a signal into trend, seasonality, and user-defined regressor effects. This assignment applies both Prophet and pyGAM to daily Walmart sales and benchmarks them against a seasonal-naive baseline and against your ARIMA/ETS results from Homework 1.

Learning objectives. By the end of this assignment you will be able to:

  • Decompose a time series into trend, weekly seasonality, yearly seasonality, and external regressors using Prophet
  • Interpret Prophet component plots and connect them to concrete business decisions
  • Fit a pyGAM with a cyclic spline for the annual cycle, a factor term for day of week, and linear terms for binary demand drivers
  • Compare GAM-family models against ARIMA/ETS on a common holdout set using RMSE

19 Dataset

This homework switches from weekly to daily data. Prophet and pyGAM both benefit from finer time granularity: daily data expose intra-week patterns that are averaged away in weekly aggregates, and Prophet’s changepoint detection is more reliable with a denser observation grid.

You will work with store CA_1, FOODS category — 1,941 daily observations from the M5/Walmart data. Note that this is the same store and category you used in Homework 1 Part 1, but at daily rather than weekly frequency, so you can compare directly against what you already fitted.

The preprocessed file is data/processed/m5_daily.csv. If it does not exist, run python scripts/prep_m5.py once from the repository root.

Why SNAP is the interesting one

SNAP (the Supplemental Nutrition Assistance Program) benefits are disbursed on fixed calendar days that vary by state. California’s schedule puts them on roughly the first ten days of each month. This is a known, published, future-dated schedule — you always know next year’s SNAP days in advance. That is what makes it usable as a forecasting regressor, and it is the property you should look for when someone proposes a predictor.

21.3 Q3 — pyGAM

(Suggested prompts: 2)

pyGAM fits an additive model directly on a feature matrix rather than on a time index, which makes it easy to include calendar-derived features and binary indicators side by side. The starter code below derives day_of_year and day_of_week from the date column and constructs training and test arrays.

Fit a LinearGAM with the following four terms:

Term Predictor Type Purpose
s(0, basis="cp") day_of_year (1–366) Cyclic spline Annual cycle, with Dec 31 joined to Jan 1
f(1) day_of_week (0–6) Factor Within-week pattern
l(2) snap Linear SNAP benefit-day lift
l(3) is_event Linear Calendar event effect

Two of those choices are deliberate and you should be able to defend them. basis="cp" makes the spline cyclic, so the fitted curve meets itself at the year boundary instead of being free to jump between December 31 and January 1. And f(1) rather than s(1): day of week takes seven discrete values with no meaningful “between,” so a factor term is the honest choice — a smooth spline would interpolate a fractional Wednesday-and-a-half.

After fitting, compute test RMSE. Then plot the partial dependence curves for day_of_year and day_of_week using the model’s plot_partial_dependence() method or by calling partial_dependence() manually.
