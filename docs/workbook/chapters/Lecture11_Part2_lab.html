Run this one live: the executable lab.

13.1 What we are doing

A hierarchical model lets thirty series share information: each gets its own effect, drawn from a common distribution the data also estimates. Data-poor series borrow from data-rich ones, and nobody has to choose the weights.

That is genuinely powerful, and today you will watch it work. You will also watch it produce a confidently wrong answer — on the same data, with clean diagnostics, textbook shrinkage, and no warning of any kind.

The difference between the two runs is not the code. It is a decision made before any code was written: which series belong in the same hierarchy.

Time: ~45 minutes · You will need: pandas, numpy, matplotlib, pymc, arviz, and data/processed/m5_weekly.csv. Six model fits, most under 30 seconds.

13.2 Setup

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import pymc as pm
import arviz as az
import warnings

warnings.filterwarnings("ignore")
RANDOM_STATE = 42

weekly = pd.read_csv("../data/processed/m5_weekly.csv", parse_dates=["week_start"])
weekly["series"] = weekly.store_id + "_" + weekly.cat_id
weekly["hi_snap"] = (weekly.snap_days >= 5).astype(int)

df = weekly.dropna(subset=["units"]).copy()
df["ly"] = np.log(df.units.clip(lower=1))

print(f"{df.series.nunique()} series | {len(df):,} rows | "
      f"{df.hi_snap.mean():.1%} of weeks are high-SNAP")

Our question: does a high-SNAP week lift units, and by how much in each store?

We will need one helper repeatedly — the SNAP effect actually observed in a set of weeks, with no model involved. It is just the difference in mean log units between high-SNAP weeks and the rest.

def empirical_effect(frame, series_name):
    """Observed high-SNAP effect on log units for one series."""
    z = frame[frame.series == series_name]
    if z.hi_snap.nunique() < 2:
        return np.nan
    return z.ly[z.hi_snap == 1].mean() - z.ly[z.hi_snap == 0].mean()

13.3 Step 1 — Build the imbalance

Real panels are lopsided: some series have years of history, others are new stores or newly re-categorized products with a handful of usable weeks. We create that imbalance deliberately so we can check the answer later.

Thin every third series down to 8 weeks. The weeks we remove are not thrown away — they become a held-out set that the model never sees, and that we will use in Step 3 to grade it.

codes, uniq = pd.factorize(df.series)
df["idx"] = codes
J = len(uniq)

rng = np.random.RandomState(RANDOM_STATE)
keep = []
for j in range(J):
    rows = df.index[df.idx == j].tolist()
    n = 8 if j % 3 == 0 else len(rows)
    keep += list(rng.choice(rows, size=min(n, len(rows)), replace=False))

train = df.loc[sorted(keep)].copy()
heldout = df.drop(index=keep).copy()
thin = np.array([j % 3 == 0 for j in range(J)])

print(f"train {len(train):,} rows | held-out {len(heldout):,} rows")
print(f"{thin.sum()} thin series (8 weeks each), {(~thin).sum()} full series")

Here is the model. It is the one from lecture, written non-centred, and it takes a flag so we can reuse it for the unpooled fit.

def fit(data, kind, n_series, centred=False, target_accept=0.9):
    """kind: 'unpooled' or 'hier'. Returns the InferenceData."""
    i = data.idx.values
    x = data.hi_snap.values.astype(float)
    y = data.ly.values
    with pm.Model():
        a = pm.Normal("a", y.mean(), 1, shape=n_series)
        s = pm.Exponential("s", 1.0)
        if kind == "unpooled":
            b = pm.Normal("b", 0, 0.5, shape=n_series)
        else:
            mu_b = pm.Normal("mu_b", 0, 0.5)
            sd_b = pm.HalfNormal("sd_b", 0.25)
            if centred:
                b = pm.Normal("b", mu_b, sd_b, shape=n_series)
            else:
                z = pm.Normal("z", 0, 1, shape=n_series)
                b = pm.Deterministic("b", mu_b + z * sd_b)
        pm.Normal("obs", mu=a[i] + b[i] * x, sigma=s, observed=y)
        return pm.sample(1000, tune=1500, chains=4, progressbar=False,
                         random_seed=RANDOM_STATE, target_accept=target_accept)

def b_means(idata, n_series):
    return az.summary(idata, var_names=["b"], ci_kind="hdi",
                      ci_prob=0.94)["mean"].values

13.4 Step 2 — Fit it, and admire the shrinkage

Fit both models on all thirty series and measure how far each estimate moved.

13.5 Step 3 — Grade it against the weeks it never saw

We thinned those ten series ourselves. The weeks we removed are sitting in heldout, and each thinned series has hundreds of them. So we can compute the effect that actually occurred and compare.

thin_names = [uniq[j] for j in range(J) if thin[j]]
truth = np.array([empirical_effect(heldout, s) for s in thin_names])
est_u = np.array([bu30[j] for j in range(J) if thin[j]])
est_h = np.array([bh30[j] for j in range(J) if thin[j]])

out = pd.DataFrame({"series": thin_names, "unpooled": est_u.round(3),
                    "hierarchical": est_h.round(3), "held_out_truth": truth.round(3)})
print(out.to_string(index=False))

rmse = lambda e: np.sqrt(np.nanmean((e - truth) ** 2))
print(f"\n  RMSE vs truth:  unpooled {rmse(est_u):.3f}   "
      f"hierarchical {rmse(est_h):.3f}")
print(f"  mean held-out effect across these series: {np.nanmean(truth):.3f}")

Read that table before reading on.

The hierarchical model reported an effect near mu_b for every one of these series. The held-out weeks say the true effects average close to 0.09 — several times larger. The model did not merely lose precision on these series; it moved them all to the wrong place, and reported tight intervals around it.

And notice what the RMSE column says: pooling barely improved on the unpooled fit at all. All that shrinkage bought us essentially nothing.

The diagnostics could never have caught this

\(\hat{R}\), ESS and divergences ask whether the sampler explored the posterior of the model you wrote. They cannot ask whether that model was the right one. Every diagnostic here passed.

13.6 Step 4 — Find out what went wrong

Two things are wrong, and one of them is invisible until you look.

First, look at which series we thinned.

print("thinned series:", thin_names)
print("\nEmpirical high-SNAP effect by category (all data, no model):")
for cat, grp in df.groupby("cat_id"):
    effs = [empirical_effect(grp, s) for s in grp.series.unique()]
    print(f"  {cat:<10s} n={len(effs):2d}  mean {np.mean(effs):+.3f}  "
          f"sd {np.std(effs):.3f}")

Two findings, and they compound.

The groups were not exchangeable. SNAP is a food assistance programme. FOODS responds; HOBBIES and HOUSEHOLD barely move. Putting all thirty in one hierarchy told the model these are thirty interchangeable draws from one distribution — so it estimated a group mean near zero, dominated by the twenty series with no effect, and pulled the FOODS series down to it.

And j % 3 == 0 selected exactly the FOODS series. The series are ordered store-major with three categories each, so every third one is a FOODS series. We starved precisely the ten series that had something to say, then pooled them toward twenty that did not.

Exchangeability is a modelling assumption, and it is yours to defend

Groups are exchangeable when, before seeing the data, you have no reason to expect one to differ from another in a particular direction. Ten FOODS series in ten stores: plausible. FOODS against HOBBIES: you knew the answer before you looked.

Nothing in PyMC checks this. No diagnostic reports it. It is subject-matter knowledge, applied before the model is written.

That is why sd_b came out at 0.008. Averaged across a group where two thirds genuinely have no effect, “stores are all the same” is the best summary of a badly-posed question.

13.8 Step 6 — The trap in the code

One more failure, and this one is mechanical. The natural way to write the hierarchy reads exactly like the equation:

b = pm.Normal("b", mu_b, sd_b, shape=J)   # the centred form

Fit it that way and watch the diagnostics.

idata_cent = fit(train_f, "hier", Jf, centred=True)

print("Diagnostics")
diag(idata_cent, "centred")
diag(idata_hf, "non-centred")

Same model. Same data. Same answer, if you could sample it — but the centred form makes the sampler walk a funnel: when sd_b is small the b_j must crowd into a narrow neck, and a sampler tuned for the wide part cannot get in.

Which alarm fired

Look at the two columns. \(\hat{R}\) is near the threshold and ESS clears 400 — on those two numbers alone you might have shipped it. The divergence count is unambiguous.

On hierarchical models, divergences are the sensitive instrument. Do not wait for \(\hat{R}\).

The natural way to write a hierarchy reads exactly like the equation: b = pm.Normal("b", mu_b, sd_b, shape=J). Everybody writes it that way first. It is called the centred form.

Diagnostics
  centred        r_hat 1.044  ess   413  divergences  127
  non-centred    r_hat 1.002  ess  1728  divergences    1

Same model. Same data. The same posterior, if you could sample it — but the centred form makes the sampler walk a funnel: when sd_b is small the individual b_j must crowd into a narrow neck, and a sampler tuned for the wide part of the funnel cannot get into the neck. Now read the three numbers as three different kinds of warning, because that is the lesson. ESS passes. 413, thirteen over the threshold. You would not look twice.

R-hat fails — 1.044 against 1.01. But be honest about what happens in practice when a number is a little over a line: people rerun it, or call it close enough, or decide the threshold is conservative.

127 divergences against a threshold of exactly zero. There is no version of “close to zero” that gets you to a hundred and twenty-seven. It admits no conversation.

So the rule: on hierarchical models, divergences fire first and least ambiguously. Do not wait for R-hat to decide for you.
