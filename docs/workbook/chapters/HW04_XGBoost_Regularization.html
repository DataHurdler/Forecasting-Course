19.1 Overview

Boosting builds trees sequentially — each new tree corrects the errors left by the previous ones. XGBoost is the dominant gradient boosting implementation for tabular data, and it often outperforms Random Forests given proper tuning. Regularized linear models (LASSO, Ridge, Elastic Net) take a different approach: they shrink coefficients toward zero, performing automatic feature selection while keeping the model interpretable.

This homework applies both families to the same M5/Walmart data as Homework 3 — but with a deliberately richer feature set — and ends with a head-to-head comparison across every method tried in the course so far.

Learning objectives:

  • Fit XGBoost and interpret gain-based feature importance
  • Tune learning_rate, max_depth, and reg_lambda using time-series cross-validation
  • Read a LASSO regularization path to identify robust vs fragile features
  • Compare LASSO, Ridge, and Elastic Net on test RMSE and sparsity
  • Synthesize walk-forward CV results across all models

19.2 Dataset and Setup

We use the same weekly M5 data and the same temporal split as Homework 3 — but we engineer many more features first, and the reason matters.

In Homework 3 you had 27 features and 5,160 training rows. With \(k\) that much smaller than \(n\), there is very little for a shrinkage penalty to do: ordinary least squares is already stable, and Ridge or LASSO will select almost no penalty. Regularization earns its keep when \(k\) is large relative to \(n\), which is exactly the situation Lecture 6 opened with.

So we build the feature set a working analyst would actually build — ten lags, rolling means and standard deviations at four windows, Fourier terms for the annual cycle, calendar variables, and one-hot identity columns — and let the penalty decide which survive.

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import xgboost as xgb
from sklearn.linear_model import Lasso, Ridge, ElasticNet, ElasticNetCV, RidgeCV
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import TimeSeriesSplit, GridSearchCV
from sklearn.metrics import mean_squared_error
import warnings
warnings.filterwarnings('ignore')

from pathlib import Path

def data_path(name):
    for base in (Path.cwd(), *Path.cwd().parents):
        p = base / "data" / "processed" / name
        if p.exists():
            return p
    raise FileNotFoundError(
        f"Could not find data/processed/{name}. "
        "Run `python scripts/prep_m5.py` from the repository root first."
    )

RANDOM_STATE = 42

weekly = (pd.read_csv(data_path("m5_weekly.csv"), parse_dates=["week_start"])
            .sort_values(["store_id", "cat_id", "week_start"]))

# --- feature engineering, per store-category series ---------------------------
g = weekly.groupby(["store_id", "cat_id"])["units"]

for L in (1, 2, 3, 4, 5, 6, 8, 13, 26, 52):        # ten lags
    weekly[f"lag{L}"] = g.shift(L)

for W in (4, 13, 26, 52):                           # rolling stats, shifted to avoid leakage
    weekly[f"roll{W}_mean"] = g.shift(1).rolling(W).mean().values
    weekly[f"roll{W}_std"]  = g.shift(1).rolling(W).std().values

weekly["month"] = weekly["week_start"].dt.month
weekly["week_of_year"] = weekly["week_start"].dt.isocalendar().week.astype(int)
weekly["year"] = weekly["week_start"].dt.year

for k in (1, 2, 3):                                 # Fourier terms for the annual cycle
    weekly[f"sin{k}"] = np.sin(2 * np.pi * k * weekly.week_of_year / 52)
    weekly[f"cos{k}"] = np.cos(2 * np.pi * k * weekly.week_of_year / 52)

df_enc = pd.get_dummies(weekly, columns=["store_id", "cat_id", "state_id"],
                        prefix=["store", "cat", "state"])

FEATURES = ([c for c in df_enc.columns
             if c.startswith(("lag", "roll", "sin", "cos", "store_", "cat_", "state_"))]
            + ["avg_price", "snap_days", "event_days", "month", "week_of_year", "year"])
TARGET = "units"

LAGGED = [c for c in FEATURES if c.startswith(("lag", "roll"))]
df = df_enc.dropna(subset=LAGGED).copy()

cutoff = pd.Timestamp("2015-05-17")          # same split as Homework 3
train = df[df["week_start"] < cutoff]
test  = df[df["week_start"] >= cutoff]

X_train, y_train = train[FEATURES].values.astype(float), train[TARGET].values
X_test,  y_test  = test[FEATURES].values.astype(float),  test[TARGET].values

print(f"k = {len(FEATURES)} features | train {len(X_train):,} rows | test {len(X_test):,} rows")
Note the .shift(1) on the rolling features

g.shift(1).rolling(W) computes each rolling statistic from data strictly before the current week. Drop the .shift(1) and the window includes the current week’s own units — the target leaking into its own predictor. Your CV error would improve and your forecast would fail. This is the same leakage failure as random k-fold, wearing different clothes.

Compute the seasonal-naive benchmark (predict units with lag52) on the test set before going further. Every model below is measured against it.

19.4.4 Q4 — Elastic Net vs LASSO vs Ridge (Suggested prompts: 2)

Lecture 6 gave two knobs: \(\lambda\) sets the total penalty, \(\alpha\) (sklearn’s l1_ratio) sets the mix. This question separates them properly.

Do not fix alpha across all five models

It is tempting to fit Lasso(alpha=100), ElasticNet(alpha=100, ...), and Ridge(alpha=100) and call that a fair comparison. It is not, for two separate reasons.

First, sklearn scales the two objectives differently. Lasso and ElasticNet minimize \(\frac{1}{2n}\|y - Xw\|^2 + \ldots\), while Ridge minimizes \(\|y - Xw\|^2 + \alpha\|w\|^2\) with no \(1/2n\) factor. With \(n \approx 5{,}000\) training rows, the same numeric alpha means penalties that differ by roughly four orders of magnitude.

Second, even within one family, the right total penalty depends on the mix — an \(\ell_2\)-heavy model needs a different \(\lambda\) than an \(\ell_1\)-heavy one to be equally regularized.

So tune \(\lambda\) separately for every mix, exactly as Lecture 6’s code slide does.

For each l1_ratio in [1.0, 0.9, 0.5, 0.1], use ElasticNetCV with alphas=np.logspace(-2, 4, 50) and cv=TimeSeriesSplit(n_splits=5) to select the best alpha. Then fit a RidgeCV with alphas=np.logspace(-2, 7, 80) and the same CV.
